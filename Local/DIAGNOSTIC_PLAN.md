# Android v1.13.0 第八轮诊断与修复计划
**时间**: 2026-10-13 17:13
**设备**: af72222f (MIUI)
**当前版本**: versionCode 72, versionName 1.13.0

## 用户反馈的核心问题

### 1. 删除功能失效（严重）
- 现象：软件内删除实例后，本地文件没有同步删除，卡片也不消失
- 代码检查：uninstallInstanceFiles 使用了 KeepAlive 前台服务持有，NativeTreeRemoval 逻辑看起来完整
- 疑点：前端可能在删除失败时没有正确处理错误，导致 UI 状态不一致

### 2. 创建/启动严重发热（严重）
- 现象："烫的要死"、"手机发热都快关机了"、"为什么别人 sillydroid 或 termux 能秒开不发热"
- 已做：.nomedia 免疫媒体扫描（第六轮）、流光去滤镜化（第七轮）
- 疑点：可能还有其他性能瓶颈（依赖归档、文件复制、WebView 初始化等）

### 3. 前端卡顿严重（严重）
- 现象："明明大型游戏都能跑，TG 那么复杂的动画都是零延迟超级流畅，我们一个网页改的前端还这么卡"
- 发现：styles.css 中有 30+ 处 backdrop-filter/blur，包括：
  - L213-214: blur(20px) saturate(1.6)
  - L234-235: blur(40px) saturate(1.5)
  - L972-973: blur(8px) saturate(1.06)
  - L1608-1609: blur(32px) saturate(1.55)
- 已做：启动器流光背景去滤镜化（第七轮），但酒馆内部还有大量毛玻璃
- 疑点：MIUI/HyperOS 的合成器对 backdrop-filter 支持差，导致强制软件光栅化

### 4. 键盘避让仍有 1-2 帧抽搐（次要）
- 已做：第七轮移除了动画起点 JS 派发
- 疑点：可能是 WebView 本身的渲染延迟

### 5. MIUI 特化过度质疑
- 用户："为什么要遵循那么多无意义的规矩？我们全程针对原生安卓进行开发"
- 需要解释：当前的窗口 insets/沉浸式/前台服务适配是防御性措施，不是无意义规矩

## 修复计划

### Phase 1: 根治删除与性能问题（最高优先级）

1. **删除功能诊断与修复**
   - 添加更详细的错误日志
   - 检查前端错误处理逻辑
   - 确保删除失败时 UI 状态正确回滚

2. **毛玻璃性能治理**
   - 全面移除或条件关闭前端所有 backdrop-filter
   - 改用纯色半透明 + box-shadow 替代
   - 保持视觉效果的前提下降低合成器压力

3. **创建/启动发热根因定位**
   - 添加性能埋点，记录各阶段耗时
   - 检查依赖归档逻辑是否有优化空间
   - 对比 Termux/SillyDroid 的实现差异

### Phase 2: 键盘优化与代码清洗

1. **键盘避让最终优化**
   - 尝试使用 CSS contain 属性隔离重排
   - 减少不必要的 DOM 操作

2. **代码清洗**
   - 清理无用残留代码
   - 检查逻辑合理性
   - 确保文件保存路径逻辑落实
